# Synthetic raw ESSENCE-like ED visit data

A fabricated dataset simulating a raw ESSENCE API data pull containing
common data quality issues: duplicate records of multiple types, non-ED
provider visits, out-of-state patient records, and `OTHER_REGION`
entries. All facility names, visit identifiers, patient identifiers, and
geographic values are entirely synthetic. No real patient or facility
data are included.

## Usage

``` r
essence_raw
```

## Format

A data frame with approximately 190 rows and 16 columns:

- HospitalName:

  Character. Synthetic facility name.

- Hospital:

  Integer. Synthetic numeric facility identifier
  (`C_BioSense_Facility_ID` equivalent).

- FacilityType:

  Character. ESSENCE facility type. Includes intentional
  misclassifications for two FSEDs (`"Urgent Care"`) to demonstrate
  [`filter_care_setting()`](https://andrew-farrey.github.io/sysPrep/reference/filter_care_setting.md)
  correction logic.

- HospitalRegion:

  Character. Facility county in `SITE_County` format (e.g.,
  `"KY_Jefferson"`).

- HospitalZip:

  Character. Facility zip code.

- Visit_ID:

  Character. Synthetic visit identifier, unique within a facility.
  Multiple rows with the same `HospitalName x Visit_ID` represent the
  duplicate patterns this package addresses.

- C_BioSense_ID:

  Character. Synthetic BioSense record identifier. Multiple values per
  `Visit_ID` indicate `visit_date_change` duplication.

- C_Unique_Patient_ID:

  Character. Synthetic patient identifier (MRN equivalent in Kentucky).
  Multiple values per `Visit_ID` indicate `pid_change` duplication.

- Date:

  Date. Visit date.

- Arrived_Date_Time:

  POSIXct. Timestamp when NSSP received the record. Use as `order_by` in
  [`dedupe()`](https://andrew-farrey.github.io/sysPrep/reference/dedupe.md)
  to retain the most recently transmitted version of each record.

- HasBeenE:

  Integer. `1` if the visit has been classified as an emergency visit.
  All records in this dataset have `HasBeenE = 1`, consistent with a
  `HasBeenE = 1` filtered ESSENCE pull.

- HasBeenAdmitted:

  Integer. `1` if the visit resulted in inpatient admission
  (discharge-disposition aware).

- Region:

  Character. Patient county of residence in `SITE_County` format.
  Includes out-of-state values (e.g., `"TN_Davidson"`) and
  `"OTHER_REGION"` entries to demonstrate
  [`assign_treating_geography()`](https://andrew-farrey.github.io/sysPrep/reference/assign_treating_geography.md).

- ZipCode:

  Character. Patient zip code. May be `NA` for `OTHER_REGION` records.

- Sex:

  Character. `"M"`, `"F"`, or `"U"` (unknown).

- C_Patient_Age:

  Integer. Patient age in years.

## Source

Entirely synthetic. Generated by `data-raw/generate_synthetic_data.R`.
Column structure models an ESSENCE `va_er` (Patient Location, Full
Details) pull, the data source against which `sysPrep`'s functions have
been validated. Encounter linkage
([`link_encounters()`](https://andrew-farrey.github.io/sysPrep/reference/link_encounters.md))
expects a supplemental inpatient pull structured as `va_hosp` (Facility
Location, Full Details).

## Details

### Duplicate patterns included

- `standard`:

  5 visits with an extra row differing only in `Arrived_Date_Time` –
  representing a record retransmission.

- `visit_date_change`:

  3 visits with a second row carrying a new `C_BioSense_ID` and a `Date`
  advanced by 1 day – representing a midnight-crossing visit where
  `Admit_Date_Time` was updated.

- `pid_change`:

  2 visits with a second row carrying a different `C_Unique_Patient_ID`
  – representing a corrected patient identifier.

- `visit_date_change+pid_change`:

  1 visit exhibiting both mechanisms simultaneously.

### Non-ED providers

20 records from a `"Primary Care"` and a `"Medical Specialty"` facility
are included. These should be excluded by
[`filter_care_setting()`](https://andrew-farrey.github.io/sysPrep/reference/filter_care_setting.md).

### FSED misclassifications

`"Hillside FSED"` and `"Downtown Emergency Services"` are onboarded with
`FacilityType = "Urgent Care"`. These require correction via
`fix_facility_type_vector` in
[`filter_care_setting()`](https://andrew-farrey.github.io/sysPrep/reference/filter_care_setting.md).
